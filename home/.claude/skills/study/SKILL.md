# study（教材を1本、脳に取り込む）

広告を作るエージェントに学習させるための入口。**教材の全文をコンテキストに入れない**のが最優先。

**このファイルの並び順は意図的。** 冒頭＝外せない関門、中盤＝参考（引くもの）、末尾＝実行手順。

# 1. 関門 — ここを通らないものは成果物にしない

## 絶対に守る2つの原則

1. **生の文字起こしを読まない。** 読むのは digest（長い教材なら元の5〜15%）と、当たりを付けた章だけ。
   **唯一の例外**: 生が8000字未満（約4000トークン）の教材。この場合は digest を挟む方が損なので
   生を直接読んでよい（digest.py が `推奨` でそう言ってくる）。それ以外で全文を読んだら失敗
2. **取得失敗を「情報が無い」と書かない。** 字幕が取れない、PDFが画像、動画に音が無い、は全部
   `FETCH_FAILED` として報告する。**空の source ページを作らない**

## 取り込む前に見るもの

- `_log.md` に同じ教材が無いか確認する。あるなら取り込まず「取り込み済み」と伝える
- 台帳（`brain.py log`）は source ページを書いてから叩く。**台帳だけ先に書かない**
  （書くと次回は重複判定で弾かれ、取りこぼしに気づけなくなる）

## source ページの書式（欄を減らさない）

**この書式は学習研究から決めている。** 根拠は
`~/.claude/skills/brain/references/learning-science.md`（層2）。

- 逐語で写したノートほど後で使えない（Mueller & Oppenheimer 2014 / 追試 Morehead et al. 2019 で
  残った部分）→ **自分の言葉に置き換える。逐語は確認用に1文だけ**
- 「なぜそうなるのか」を書かせると転移が上がる（Chi et al. 1989 の自己説明、
  Woloshyn et al. 1990 の精緻化質問）→ **理由欄は必須**
- LLMが読むノートに「書いた効果」は乗らない。乗るのは保管物としての質だけ
  （Kobayashi 2005）→ **書式を固定して機械が検査できる形にする**

**何を残して何を捨てるかは `~/.claude/skills/brain/references/note-standard.md` が正。**
主張は claim 単位（前後の文脈なしで単体で読めること）。残すのは
**[事実] / [手法] / [逆張り] / [失敗] / [接続]** の5種だけで、感想と一般論は捨てる。
各 claim に `[出所 | 承認状態 | 位置 | 発信日 | 取得日]` を付ける（**発信日と取得日は別物**）。
矛盾する主張は消さずに `⇄反証:` で両論併記。API・モデル序列・広告相場のように腐る話は
主張文の中に「時点情報(YYYY-MM)」を書く。承認状態は
`~/.claude/skills/brain/references/sources.md` の台帳と照合し、無いソースは「未承認」で追記する。

```markdown
---
slug: <slug>
title: <教材名>
kind: youtube | video | pdf | web
source: <URL かファイルパス>
studied: YYYY-MM-DD
raw: raw/<slug>.txt
topics: [advertorial, hook, offer]
grain: 事実 | 関係 | 転移
---

# <教材名>

## この教材が答えている問い
（問いの形で1つ。「〜とは何か」ではなく「〜する時にどうするか」の形にする）

## 主張

c01
- 何を言っているか: <自分の言葉に置き換えた1行。次に手が動く形にする>
- なぜそうなるのか: <教材が挙げた理由。言っていなければ「理由の記載なし」と書く>
- どこまで効くか: <条件・前提・使えない場面。書いていなければ「境界の記載なし」>
- これが正しいなら: <この主張が本当なら観測できるはずのこと。後で検算するため>
- 逐語: "<原文1文だけ>"

c02
- ...

## 採らなかった主張
（読んだが使わないと決めたもの。`- c07: 理由` の形。無ければ「なし」）

## 数字
（教材が出した具体的な数字だけ。形容詞は書かない）

## この教材が言っていないこと
（穴。後で別の教材で埋める対象になる）

## 既存の知識との関係
（一致 / 矛盾 / 新規 のどれか。矛盾なら相手の playbook 名と論点を書く）
```

**縛り**

- `c01` から通し番号。この番号が playbook から引かれ、機械が検査する
- 「〜が大事」で終わらせない。**何を、いくつ、どの順で、まで書く**
- 教材が言っていないことを足さない。推測を書くなら「（推測）」と明記する
- **主張は全部どこかに行き先を持たせる。** playbook に入れないなら「採らなかった主張」に書く
  （黙って落とすと後で `selftest.py coverage` が拾う）

## 見るものと見ないもの

- 生の `.txt` は**絶対に Read しない**
- コンタクトシートは1枚＋気になる数枚まで。**出た画像を全部は見ない**
- 「機械抽出に引っかからなかった章」は**捨てる理由にならない**。具体例・ケーススタディ・
  実演は目印の語を含まないことが多い

## 測れないこと（この仕組みの限界）

- **digest が拾えるのは言葉になっている主張だけ。** 画面に映っている図・ダッシュボード・
  実演の手つきは1文字も入らない。UIの操作を教える教材はこのスキルでは半分しか学べない
- **whisper は固有名詞と数字を間違える。** 金額・ツール名・人名は、そのまま playbook に
  書く前に slice で前後を確認する
- **YouTubeの自動字幕は話者を区別しない。** 対談形式は誰の主張か分からなくなる
- **抽出の目印は日本語と英語だけ。** 他言語の教材はほぼ拾えない

# 2. 参考 — 実測で分かっていること（引くもの。通読しない）

## 失敗したときの分岐

| 出たもの | 意味 | やること |
|---|---|---|
| `FETCH_FAILED: whisperのモデルが無い` | 初回のみ | 表示されたcurlを実行（1.6GB、1回だけ） |
| `FETCH_FAILED: PDF N ページ中 M ページが取れない` | 画像PDF | OCRが要る。このスキルでは扱えないとユーザーに言う |
| `FETCH_FAILED: 音声トラックが空` | 無音動画 | 画面だけの教材。今は非対応 |
| `FETCH_FAILED: Web取得に3回失敗` | ブロック | 「記事が無い」ではなく「取れなかった」と報告する |
| `FETCH_FAILED: ブロック/ログイン画面を掴んでいる` | 有料記事等 | 本文が取れていない。学習させない |
| `FETCH_FAILED: リンク一覧ページを掴んでいる` | URL違い | 記事本文のURLを渡し直す |
| `FETCH_FAILED: 『字幕が無い』とは確認できていない` | YouTubeの障害 | 20分置いて再実行。急ぐなら `--force-whisper` |
| `注意: 前回の X.txt は X.stale-*.txt に退避した` | 再取得の失敗 | 古い教材が混ざるのを防いだ。取得し直すまで digest を回さない |
| `DIGEST_FAILED: 生テキストが空` | 取得失敗 | Step 2 に戻る。空のページを作らない |
| `SLICE_FAILED: 章Nは無い` | 章番号ずれ | `--chapters` を付けずに呼び直す |
| `LOG_FAILED: --claims N だが…` | 数の不一致 | source の主張リストと数を合わせる |

## 取得の実測（2026-08-14）

- `yt-dlp` の字幕取得は動く。ただし複数言語を一度に取ると一部が `HTTP 429` で落ちる。
  1言語ずつ取る設計にしてある。`-orig` 付きが元言語なので優先する
- YouTubeの自動字幕は同じ文を2〜3回繰り返す形式。そのまま読むとトークンが2〜3倍になる。
  `fetch.py` の `parse_vtt` で重複を落としている
- `whisper-cli`（whisper.cpp 1.9.1）はインストール済み。モデルは
  `~/.cache/whisper/ggml-large-v3-turbo.bin`（1.6GB、ダウンロード済み）
- `pdftotext` は入っていない。PDFは `pypdf 6.15.0` を使う
- Webページは `r.jina.ai` 経由。**ブラウザのUAだと403**なので素のUAで投げている

## 映像の実測（2026-08-15）

- `grab.mjs` は33分の動画から24枚を**12秒**で取り、コンタクトシート1枚（1960x1832）にした。
  Miroの図・実物のLP・チェックアウト画面・スマホ表示まで、話の流れが1枚で追える
- `--embed` を付けると `Target page has been closed` で落ちた。**素の watch URL を渡すこと**
- **プリロール広告を踏むと、広告25秒を24分割したシートができる**（実測で発生。中身は全部広告）。
  `--expect <本編の秒数>` を必ず渡すこと。広告が明けて長さが一致するまで待ち、
  一致しなければシートを作らずに落ちる。秒数は
  `yt-dlp --flat-playlist --print "%(id)s %(duration)s" <channel>` で一括で取れる
- `yt.mjs` は同じ動画の手動字幕を8秒で取得（41,936字）。字幕側は fetch.py と役割が重なるので、
  どちらか一方でいい
- 場面変化が0件になる動画（ずっと同じ画面）は自動で等間隔30秒に切り替わる。
  音声だけの教材にかけても意味が無いので、その場合は飛ばす
- PDFのスライドは動画より効率がいい。`pymupdf` でページ画像にできる

# 3. 実行手順

## Step 0. 脳があるか確認する

```bash
python3 ~/.claude/skills/brain/scripts/brain.py stats || \
python3 ~/.claude/skills/brain/scripts/brain.py init
```

`stats` は未初期化なら終了コード4で落ちるので、この書き方で init が走る。
置き場所は `Obsidian Vault/ec/wiki/ads-brain/`。

## Step 1. 重複を先に見る

`_log.md` に同じ教材が無いか確認する。

## Step 2. 生テキストにする

```bash
python3 ~/.claude/skills/study/scripts/fetch.py "<入力>" \
  --out "<ads-brain>/raw" --slug <slug> --lang auto [--keep-video]
```

- YouTube → まず字幕を無料で取る。無ければ音声を落として whisper（ローカル、無料）
- ローカル動画・音声 → whisper
- PDF → pypdf。画像PDFは弾かれる（OCR未対応）
- Webページ → r.jina.ai でMarkdown化
- `--keep-video` を付けると、YouTubeの動画本体も480pで `raw/video/<slug>.mp4` に残す。
  **画面（LP・広告・Shopify管理画面）を見る必要がある教材では必ず付ける**

slug は `YYYY-MM-DD-<内容が分かる短い名前>` にする。例 `2026-08-14-alex-advertorial`。

## Step 3. digest に潰す

```bash
python3 ~/.claude/skills/study/scripts/digest.py "<raw>/<slug>.txt"
```

出るのは章立てと、各章から機械抽出した「指示・数字・禁止・失敗談・型の名前」だけ。
出力JSONの `推奨` に従う（`圧縮が甘い` と言われたら `--per-chapter` を下げて取り直す。判定は20%が境目）。

**`omitted_chapters` に番号が入っていたら、その章は digest に載っていない。**
中身が無いのではなく、字数上限で落ちただけ。必要なら slice.py で直接見る。

## Step 4. digest を読んで、掘る章を決める

判断するのは1つだけ。**「広告を作る時に手が動く情報が入っている章はどれか」**。掘るのは普通 3〜6章。

## Step 5. 決めた章だけ全文で取る

```bash
python3 ~/.claude/skills/study/scripts/slice.py "<raw>/<slug>.txt" --ch 3,7,9
```

`--chapters` は書かない（digest が使った章割りを自動で読むので番号がずれない）。
語で探したいときは `--grep "アドバトリアル" --window 400`。

## Step 5.5. 動画なら、見た目も取る

**画面共有・スライド・広告の実物が映る教材は、文字起こしだけだと半分しか学べない。**

**YouTubeは grab.mjs が本線。** 動画をダウンロードせず、稼働中のChromium（CDP 9222）を
操作して等間隔にシークしてスクショし、**時刻ラベル付きの1枚のコンタクトシート**に連結する。
24枚が画像1枚（約1.5kトークン）で読めるので、1枚ずつ見るより10倍安い。

```bash
node ~/.claude/skills/study/scripts/kit/grab.mjs "<watch URL>" \
  --points 24 --cols 4 --out <ads-brain>/frames
```

- 先に `curl -s http://127.0.0.1:9222/json/version` でCDPブラウザが生きているか見る
  （このブラウザは1本しかないので**並列で叩かない**）
- 出力は `<out>/<videoId>/montage_01.jpg`。**まずこれを1枚 Read する**
- 気になる時刻があれば `frames/beat_NNN.jpg` を個別に Read して拡大確認する

**ローカル動画・落とせるmp4** は `av.mjs`（並列可）。
**最後の手段**として `frames.py`（場面変化＋知覚ハッシュ＋文字らしさで選別、Step 2 の
`--keep-video` で落とした mp4 が要る）。

画像を見たら、source の主張欄に「画面で何が示されていたか」を必ず書く。
言葉になっていない情報（レイアウト、色、並び順）はここでしか拾えない。

## Step 6. source ページを書く

`<ads-brain>/sources/<slug>.md` に、冒頭の関門の型で書く。

## Step 7. 台帳に書く

```bash
python3 ~/.claude/skills/brain/scripts/brain.py log \
  --slug <slug> --title "<教材名>" --kind <種別> --source "<出所>" --claims <主張の数>
```

`log` は source ページの実在・frontmatterのslug一致・主張リストの本数を検査してから書く。

既存の playbook と食い違っていて、その場で裁定できない教材は `--status 保留` で載せる
（保留は `check` の未統合リストから外れる）。

## Step 8. 報告する

- 元の量 → digest の量（圧縮率）
- 掘った章と、その理由
- 取れた主張の数と、そのうち「そのまま使える型」がいくつか
- **既存の playbook と食い違う主張があれば必ず名指しで挙げる**（/brain の裁定材料）
- 最後に「`/brain` で統合するか」を出す

</procedure>
