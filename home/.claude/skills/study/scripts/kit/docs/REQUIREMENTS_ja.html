task-fleet · 動画インプット脚 / video ingest

動画を「見る」前に、
機械経路で畳んで取り込む。

YouTube などの動画を、人間が全部再生して目視する代わりに 機械経路で必要なコマだけ抜き取り、下流の解析にそのまま渡せる形（文字起こし JSON ／時刻ラベル付きコンタクトシート）へ畳み込む脚。喋り（テキスト）と 映像 の2レイヤーで構成する。この文書は、別環境にそのまま導入するための要件定義・依存関係・手順・落とし穴をまとめたもの。

4 scripts runtime: node + python3 deps: yt-dlp · ffmpeg · Pillow · playwright 検証: 2026-08-15
§01

概要 — 何をする脚か

中核の原則は一つ。「動画は見る／聴く前に、機械経路で畳んで取る。ブラウザ描画も実時間再生も最小化する」。全フレームを人手で見るのではなく、意味の変わり目だけを抜き、1枚の一覧にして vision 解析へ渡す。取り込みは目的で2レイヤーに分かれる。

喋りレイヤー yt.mjs TEXT ONLY

「何を言ったか」が要るとき。字幕(VTT)を yt-dlp で並列取得し、タイムスタンプ・タグ・重複を除去したクリーンな文字起こし JSON にして返す。

  • チャンネル/ハンドル/プレイリストを渡すと 全動画へ展開してから並列処理
  • 手動字幕→自動字幕の順、言語優先指定可
  • 字幕が取れなければ 1回リトライ→降格（route:"browser"）
  • 映像・画面・テロップは取らない

映像レイヤー av.mjs · grab.mjs VISUAL

「どう見せたか」（カット割り・テロップ・見せ方）が要るとき。フレームを抜いて contact.py が時刻ラベル付きモンタージュに畳む。

  • av.mjs — DL可能な動画（ローカル / Meta・TikTok の直CDN .mp4）を ffmpeg シーン検出でカット抽出。並列可
  • grab.mjs — YouTube 等を稼働中 Chromium に CDP 接続→seek→スクショ。実時間再生でないので速い。直列
  • contact.py — PIL で時刻ラベル付きコンタクトシート生成
§02

なぜ映像に2経路あるのか

映像の取得元によって道が分かれるのは、YouTube のメディア取得が構造的に固いから。ここは設計の肝なので明示しておく。

403

YouTube のメディア（動画バイト）ダウンロードは今や PO token 必須で、yt-dlp が HTTP 403 Forbidden で弾かれる。

字幕エンドポイントは通る（＝yt.mjs は成立する）が、動画本体の取得は不可。--cookies-from-browser による回避も、現行 Chrome の App-Bound Encryption で cookie が復号できず失敗する（Extracted 0 cookies）。

したがって取得元 → 経路の対応はこうなる。

取得元喋り(字幕)映像並列
YouTubeyt.mjs OKgrab.mjs（ブラウザ捕獲）直列
Meta 広告ライブラリ / gethookd—av.mjs（直CDN .mp4）並列
TikTok—av.mjs（yt-dlp が通る範囲）並列
ローカルファイル—av.mjs（.mp4 を直入力）並列

要は YouTube の映像は grab.mjs（ブラウザ捕獲）が本線、DL可能なソースは av.mjs で並列。EC 広告の主戦場（Meta / gethookd）は直CDN が取れるので av 側で回る。

§05

セットアップ手順

  1. スクリプトを置く

    4ファイルを ~/.claude/skills/task-fleet/scripts/ に配置する。

    files
    ~/.claude/skills/task-fleet/scripts/
├── yt.mjs        # 喋り(字幕)
├── av.mjs        # 映像・DL可ソース
├── grab.mjs      # 映像・YouTube(ブラウザ捕獲)
└── contact.py    # モンタージュ生成(PIL)

  2. 依存を入れる

    bash
    brew install node ffmpeg yt-dlp
pip3 install -U yt-dlp Pillow

    ffmpeg -version / yt-dlp --version / python3 -c "import PIL" が通れば OK。

  3. grab.mjs 用のブラウザを常駐させる

    grab.mjs は browser-agent スキルの Chromium を CDP ポート 9222 で使う。スキルを入れて起動し、その profile で YouTube に一度ログインしておく（アクセス安定のため）。

    bash
    # browser-agent を用意（初回のみ）
cd ~/.claude/skills/browser-agent
npm i && npx playwright install chromium

# CDP ブラウザを 9222 で起動（launch.sh / env CDP_PORT）
bash scripts/launch.sh
    check

    別ターミナルで curl -s http://127.0.0.1:9222/json/version が JSON を返せば CDP は生きている。

  4. スモークテスト

    3経路を最小コマンドで通す。

    bash — smoke
    # ① 喋り: 字幕が ok:true / manual-sub で返るか
node scripts/yt.mjs "https://www.youtube.com/watch?v=dQw4w9WgXcQ"

# ② 映像(YouTube): 8フレーム + montage が出るか
node scripts/grab.mjs "https://www.youtube.com/watch?v=dQw4w9WgXcQ" --points 8

# ③ 映像(DL可): ローカル/直CDN の .mp4 で montage が出るか
node scripts/av.mjs ./some.mp4 --max-frames 12

    実測(2026-08-15): ①manual-sub/en 351語, ②12frames/5.3s(フル3:33を12点seek), ③ローカルmp4 10frames/0.4s。

§08

既知の制約 / blindspot

字幕なし動画

yt.mjs は字幕が無いと route:"browser" に降格してそこで止まる（音声書き起こしのフォールバックは無い）。喋りが要るなら別途 whisper 等を足す。

grab は直列

共有ブラウザ1台(CDP)を使うため 並列にできない。多本を回すなら逐次。DL可能なソースは av.mjs の並列へ寄せる。

プレイヤーUIの写り込み

grab.mjs は捕獲前に YouTube のコントロール/サジェスト/エンドカードを CSS で消して素フレームにしている。ただし焼き込み字幕は残る（むしろテロップ解析に有用）。

テキストと映像は別物

yt.mjs は映像を一切取らない。「どう見せたか」が要るタスクで yt.mjs を使うと骨格が抜ける。用途で使い分ける。

トラブルシュート

導入時に実際に踏んだ落とし穴と対処。

症状原因対処
HTTP Error 403
(yt-dlp DL時)		 YouTube のメディアが PO token 必須 YT の映像は grab.mjs を使う。DL可能なら直 .mp4 を av.mjs に食わせる
no subtitles
after retry		 その動画に字幕が無い route:"browser" 降格。喋りが要るなら whisper、映像なら grab.mjs
No such filter:
'drawtext'		 ffmpeg が libfreetype 欠き 正常。ラベルは contact.py(PIL)が付ける。Pillow を確認

duration NaN /

Extracted 0 cookies
(could not be decrypted)		 Chrome の App-Bound Encryption cookies-from-browser は諦める。grab.mjs のライブ session をそのまま使う
