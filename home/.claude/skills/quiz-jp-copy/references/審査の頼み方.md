# 審査の頼み方（手順7）

読む人: quiz-jp-copy で審査役と読み手の目を呼ぶ Claude。
読む時: 手順7に入る時。審査の頼み方を変える時。
読まなくていい条件: なし。

審査は2人に分ける。どちらも新しい文脈の Opus のサブエージェント（`model: "opus"`・結果を待つ形 `run_in_background: false`）。審査役と読み手の目には、結果を決めたファイル（審査_<何本目>_<回>.md・読み手の目_<何本目>_<回>.md）に書かせる。作る側は、そのファイルの1行目が埋まるまで番を終えずに待つ（`until [ -s <ファイル> ] && ! head -1 <ファイル> | grep -q '答え合わせ）'; do sleep 30; done`）。結果を待つ形で呼んでも裏で動いて知らせで返る事があり、番を終えると知らせを受け取る側がいなくなって止まる（2026-10-10 2本目で2回、読み手の目の答え合わせの手前で止まった）。作った自分では判定しない。

## 1人目: 審査役

| 渡す物（全部） | 渡さない物 |
|---|---|
| 参考の段の表・参考の画面・出来た物の画面（幅390 と 1280）・見比べ_動き.jpg・本物の商品写真と作った画像を並べた1枚・移植表・最終確認の箱の文・質の手本（ここちドライ https://kokochidry.shop/pages/advertorial-08 と advertorial-05 の画面） | 作った Claude の考え・前の回の会話・型のノート（渡すと「この並びでないとダメ」と読んで落とす。並びは機械の検査がもう見た。2026-10-10 の較正2回目で本人の OK 2件をこれで落とした） |

見させる事（基準ごとに「理由 → ○×」の順で1行ずつ）:

| 基準 | 見る所 |
|---|---|
| 前の回の直し | 前の審査で直すべきだった所が直ったか（2回目から。先にこれ） |
| 段ごとの効果 | 段ごとに、画面で参考と同じ心理の効果（好奇心・怖さ・安心・急ぎ）が起きているか |
| 質 | 字・文・画像の質・紹介の欄・値段の段が、質の手本と同じか。細長い写真・字の崩れ・AIっぽい見た目 |
| 分かりやすさ | 初めて読んだ人が一度で分かるか |
| 動く物と商品の形 | 見比べ_動き.jpg（上が参考・下がうち）で、動く物の画面の割り・カットの順・面ごとの実写か AI かが参考と同じか。本物の商品写真と並べた1枚で、商品の形（粒・模様・裏・色・縁）が同じか（2026-10-11 本人） |

×にする線: 基準ごとに、一目で分かる崩れ（字の崩れ・細長い写真・空いた欄・読めない画像）が1つでもあれば×。空いた欄は「未定」の札・名前も顔も無い紹介・誰かの紹介でなくセリフになった紹介の欄・参考にある保証や声を「決まったら足す」で抜いた物も入る。言い回しの好みや小さな違いは×にせず「直すと良い所」に書くだけ（較正2回目で、小さな食い違いだけで本人の OK を落とした）。
×にしない物: 1日あたり・人数・出どころのような数字の計算や食い違い（本人「数字系は本当に気にしないで欲しい」10/9）と、質の手本の画面にも同じ見え方がある物（手本が本人の ○ の線）。どちらも「直すと良い所」に書く（較正3回目で、手本 advertorial-05 そのものを「1日あたり5円」の計算と見出しの2行折れで落とした）。

見させない事: `data-*` の印・✅の行数・問いの数・段の数のように、機械の検査がもう見た形の決まり。審査役は形でなく画面での効き目を見る（2026-10-10 の較正で、形で落とした審査役は本人の OK 3件を3件とも落とした。`~/Claude Code/kata-tsukuru/runs/較正_記事/_審査役の較正_2026-10-10.md`）。

ファイル `審査_<何本目>_<回>.md` の形:

```
PASS か FAIL: <理由>
## 受け取った物
- 参考の段の表 … / 参考の画面 … / 出来た物の画面 … / 移植表 … / 最終確認 …
## 基準
- 前の回の直し: <理由> → ○
- 段ごとの効果: <理由> → ○
- 質: <理由> → ○
- 分かりやすさ: <理由> → ○
```

## 2人目: 読み手の目

- 参考も、足した場所も見せない。出来た物の画面（幅390を上から全部）だけを渡す
- 聞く事は1つ:「浮いて見える・流れが切れる所・中身が弱い所」を、画面の番号・何が・なぜ・強中弱、と種類（浮き＝見た目か文の調子が周りと違う／切れ＝前後の話がつながらない／中身＝文の言っている事が弱い／押しつけ＝脅されている・急かされていると感じる）で。「押しつけ」の強か中が最悪の結末の箱か「最後まで読んでほしい」の文に挙がったら FAIL（2026-10-11 本人）
- 答え合わせは作る側がする。`data-tasu` の段の位置に、種類が「浮き」か「切れ」の強か中が挙がっていなければ、1行目に `PASS`。挙がっていれば `FAIL: <画面と中身>` と書き、その段を手順3に戻して直す。足した段が前後の段と食い違う物（前で全員に見せた値段を、後で「答えた方だけ」と言う、の類）は、中身に見えても「切れ」として FAIL にする。前後と食い違わない「中身」だけを FAIL にせず、審査役の次の回の「前の回の直し」に回す（2026-10-10 2本目: 値段の食い違いを中身として外しかけた。原因を割った別の AI が、切れだと見つけた）
- 比べる物を持たせる: 同じ頼み方で、参考のページ（幅390の全画面）にも読み手の目を1回当てる（参考ごとに1回でよい。`読み手の目_参考_<参考の番号>.md` に残して使い回す）。うちのページの挙がった物のうち、参考でも同じ所・同じ理由で挙がった物は「参考どおり」として FAIL に数えない（参考との差を0にする決まりなので）。FAIL にするのは、うちのページだけで挙がった浮き・切れの強・中（2026-10-10 2本目: 比べる物が無く、日本の通販の書き方（期限のくり返し）を回ごとに落として、5回回しても収まらなかった）。参考の読み手の目が挙げなかった所でも、移植表で参考の同じ段に同じ働きの文がある（参考の文を訳して移した）物は「参考どおり」として FAIL に数えない（2026-10-11 本人。ここちドライ暴露型の5回目で、参考にもある値段の段の期限の3文が、参考側でたまたま挙がらなかっただけで落ちた）
- 2回目からは、先に前の回に挙がった所が直ったかだけを見て、直っていなければ FAIL。新しく挙がった所で FAIL にするのは、その回の直しで入った（前の回の画面に無かった）文や見た目だけ。前の回の画面にもあって挙がらなかった所が新しく挙がった物は、FAIL にせず `直しの案` に回す（2026-10-11 本人。読み手の目が回ごとに別の所を挙げ、上限4回で通らなかった）
- 保存は `読み手の目_<何本目>_<回>.md`（1行目が答え合わせ、2行目から審査役の一覧をそのまま）

## 審査の頼み方を変えた時

`~/Claude Code/kata-tsukuru/runs/較正_記事/` の見本（本人の判定つき）に通し、本人の判定と全部合うのを確かめてから使う。合わない所は、この節の「見させる事」を直す。
