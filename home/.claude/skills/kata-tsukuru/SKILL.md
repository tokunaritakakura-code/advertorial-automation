# kata-tsukuru — 飛び先の型を見つけて、写して作る子スキルまで作る

読む人: 飛び先の型を作る Claude。
読む時: 新しい型を作る時・作った子スキルが×を出した時。
読まなくていい条件: 型が決まっていて1本作るだけの時（子スキルを使う）。

本人が「この型はこう割って、共通項はこれで、このスキルを作って」と言わなくても、型の発見から子スキルの完成まで1つの Claude が回し切るスキル。ゴールは `GOAL.md` のチェックボックス7個で、判定は道具（`scripts/goal.py check`）がする。全部○になるまで回し、本人に返すのは通った後の1回だけ。

このファイルの並び順は意図的。冒頭＝外せない関門、中盤＝参考（引く物）、末尾＝実行手順。

| やりたいこと | どこを読む |
|---|---|
| リンクを渡されていない・毎朝の型さがし | 関門の「採用の線」→ 手順00 |
| リンクを1本渡された | 手順0 |
| 線を超えた構造を型にする | 手順1〜11 |
| 探し場所が使えない・新しい場所を見つけた | 参考の「参考の出どころ」の表 |
| 箱が×になった | 関門の「ループの決まり」 |

# 1. 関門 — ここを通らないものは成果物にしない

## 着手ゲート（無ければ着手しない）

| 要る物 | 無い時 |

| 判定 | 線 |

## ゴール（/goal）

ゴールは作業場の `GOAL.md`。箱は7個で、中身は `scripts/goal.py` の `BOXES` が正本（ここに写さない）。

- 箱に○を付けるのは `python3 ~/.claude/skills/kata-tsukuru/scripts/goal.py check <型>` だけ。手で○を付けない（道具が GOAL.md を塗り直す）
- 終了コード: 0＝全部○（本人に出してよい）／1＝×あり（ループを続ける）／2＝作業場が無い／3＝周回の上限8回（本人に1行）

## ループの決まり（回し切る）

1. 途中で止めて本人に報告しない。途中経過も返さない。×は自分で直して次の周回へ
2. ×が出たら `goal.py fail <型> <箱> "<理由1行>"`。理由は次に直す所を指す（「G3 ×」でなく「固定の『問いの数』が2本の参考にしか出ていない」）
3. 同じ箱が2回×になったら、同じやり方をもう一度回さない。新しい文脈の Opus のサブエージェントに、その箱の×の理由2回分・出来た物・その箱を作る手順を渡し、「試みに共通する前提を1つ」「手順が足りないのか・道具が測れていないのか・参考が足りないのか」「直し方1案」を5行で返させてから、その箱を作る手順か道具を直して戻る（作った本人には自分の前提が見えない）。同じ箱が同じ理由で3回×になったら、8周を待たずに止めて本人に1行（`goal.py fail` が終了コード3を返す）
4. 直しは「しない一覧」や別の md にしない。子スキルのその作業をする手順の位置に1行差し込み、`直しの記録.md` に `- <日付> 手順N に入れた: <中身> / 止める検査: <検査の項目名 か 見本の番号>` で1行残す（G7 が数える。2026-10-09 本人の決め）。×が出た実物は `見本/<番号>_<名前>.md` に「落ちた物 → 今は何が落とすか」の表で残し、直した後は見本の物をもう一度検査と審査に通して、他を壊していないか確かめる（文だけの直しは破れるので、落ちた物を必ず落とす検査か見本に結ぶ）。子スキルを初めて全部○で出した後に足した直しが15行を超えたら、差し込みを続けずに、型.md と直しの記録から子スキルを作り直し、見本を全部通す（継ぎはぎで焦点がぼけるのを止める。15行は目安）
5. 周回の上限は8。超えたら本人に1行だけ: どの箱が何回×で、何を試したか
6. お金のかかる生成（動画・有料の画像）は E2E で使わない。画像は ChatGPT の MCP の範囲で作る

## 成果物に出してよいもの

- `goal.py check` が終了コード0を出した後の子スキル（`~/.claude/skills/<子スキル>/`）と、型の資料（Vault に置いた写し）
- 本人への報告は5行以内: 何の型の子スキルが出来たか・本物の入力で何を作ったか（開ける場所）・本人の次の一手

## 言葉

## 子スキルの形

## 測れない物（限界）

- 参考の売上・転換率は分からない。「30日以上・広告5本以上出している＝勝っている」は仮説として扱い、型.md に書く時もそう書く

- クイズの全部の分岐は辿り切れないことがある。辿った道（選んだ答え）を refs に書く

# 3. 実行手順（毎回この順。飛ばさない）

00. **自分から探す（リンクを渡されていない時・毎朝の型さがし）**: 入力は広告のフォーマット1つ（static・VSL・ネイティブ広告。新しいフォーマットでも同じ骨組み）。選んだ出どころと理由を `~/Claude Code/kata-tsukuru/runs/_さがし/<日付>_<フォーマット>.md` に1行ずつ書く。割った記事は `runs/_さがし/<日付>_<フォーマット>/<ドメイン>__<道の最後>/`（同じドメインで道が違う記事がぶつかるため）、採用に届かなかった構造は `runs/_さがし/候補の棚.md`。止めるのは、「商品を知っている」以外の3段階で同じ構造の記事が3本そろった時か、記事に飛ぶ広告を100本見た時（社の数では止めない。2026-10-11 試験で10社では記事が段階ごとに1本しか無かった）。「商品を知っている」段階は数えるが型にしない（決めたこと 2026-10-11「商品を知っている人向けは商品ページ直行」）
