# SKILL.md の書式 — 全スキル共通の基準

根拠は Anthropic のプロンプト公式ドキュメントと、位置バイアスの研究。
**思いつきで形を変えない。** 変えたくなったらこのファイルを直し、全スキルに反映する。

## なぜ形が効くのか（3つだけ覚える）

1. **長い資料は上、実行させたい指示は下。** 公式に「Queries at the end can improve response
   quality by up to 30 percent in tests」と明記。指示が上・資料が下は逆順。
2. **真ん中は読まれにくい。** 冒頭と末尾が強く、中間が弱いU字。長いファイルの中間に置いた規則は、
   書いた側が思っているほど効いていない。
3. **形式で縛ると推論が落ちる。** 文章で考えさせてから機械可読の形に変換する。
   最初からJSONで書かせない（Tam et al. 2024, arXiv 2408.02442）。

## 並び順（固定）

```
---
frontmatter（name / description）
---

# タイトル
1〜2段落の要約。何のスキルか、いつ飛ばしてよいか。
「このファイルの並び順は意図的」の1行。

<gates>
# 1. 関門 — ここを通らないものは成果物にしない
  着手ゲート（入力条件。無ければ着手しない）
  契約（状態・終了コード・何を成功と呼ぶか）
  合格の定義（受け入れ条件の表）
  成果物に出してよいもの
</gates>

<reference>
# 2. 参考 — 実測で分かっていること（引くもの。通読しない）
  テーマ別に整理。日付順に並べない
  測れないもの / 限界
</reference>

<procedure>
# 3. 実行手順
  Step 1..N。コマンドと読み方
  保存先
  前後の工程
</procedure>
```

**関門が冒頭、参考が中盤、手順が末尾。** 中間が弱い位置なので、そこには「引けばいいもの」を置く。
関門と手順は強い位置に置く。

## 書き方の規則

| 規則 | なぜ |
|---|---|
| **肯定形で書く**（「Xしない」より「Yする」） | 否定形は守られにくい |
| **理由を1行添える** | 理由があると、書いていないケースにも応用が効く。ルールを100個並べるより理由を10個 |
| **同じ規則を2箇所に書かない。1箇所に書いて他はそこを指す** | 片方だけ古くなる。実例: voc-research のブロック判定が um.py だけ直り voc.py が1年古いままだった |
| **日付ブロックを積み上げない。テーマ別に畳む** | 同じ対象の話が3箇所に散ると、触るたびに全部探すことになる |
| **例は3〜5個**。多すぎても少なすぎても効かない | 公式の推奨 |
| **表にできるものは表にする** | 条件と対処の対応が一目で追える |
| **決定的な処理はコードに落とし、SKILL.mdからはそこを指す** | 文章の規則は破れるが、コードの規則は破れない |
| **500行以内** | 超えたら `references/` に分ける |

## 出力の形

- 考察・判断は**文章**で書かせる
- 次の工程が機械で読む部分だけ**JSON**にする
- 状態（テスト結果・進捗・ステータス）は JSON、経過メモは自由文

## 改修したときの確認

書き換えたら、**旧版の固有トークンが新版に残っているかを機械照合する。**
目視で「大丈夫そう」は使わない。

**照合は必ず両方向やる。片方だけでは足りない。**

```bash
# ① 落ちていないか（旧 → 新）
python3 ~/.claude/skills/skill-creator/references/check-nolost.py <旧ファイル> <新ファイル>
# ② 勝手に足していないか（新 → 旧）← こちらを飛ばすと、書き換えのたびに規則が発明される
python3 ~/.claude/skills/skill-creator/references/check-drift.py  <旧ファイル> <新ファイル>
```

①で落ちたトークンは、意図した削除か事故かを1つずつ判断する。
②で増えたトークンは、**元に無かった規則・数字・パスを発明していないか**を1つずつ確かめる。
実例（2026-08-22）: 32本を書き換えた時、`/website-copy` に別スキル（`/store`）の知見を
黙って持ち込んでいた。①は0件で通っていたので、②が無ければ発見できなかった。

**書き換えたら、本文が指しているファイルが実在するかも見る。**

```bash
grep -oE '`(references|scripts)/[^`]+`' <新ファイル> | tr -d '`' | while read p; do
  [ -e "$(dirname <新ファイル>)/$p" ] || echo "参照先が無い: $p"
done
```
