# Skill Creator（ローカル改訂版）

スキルを「書いて終わり」にしない。
**動くことを実測で証明し、第三者(Codex)レビューを通ってから完成**とする。

**このファイルの並び順は意図的。** 冒頭＝外せない関門、中盤＝参考、末尾＝実行手順。

# 1. 関門 — ここを通らないものは成果物にしない

## 6ステップは順番固定・スキップ禁止

ユーザーが明示的に「テスト不要」と言った場合のみ省略可。

| # | ステップ | 必須か |
|---|---|---|
| 1 | 意図の確定 | — |
| 2 | **プラン検証（実装前ゲート）** | **必須** |
| 3 | 実装 | — |
| 4 | **E2Eテスト（実測ゲート）** | **必須** |
| 5 | **Codexレビュー** | **必須** |
| 6 | 登録+報告 | — |

## 書式は1箇所に固定してある

**`references/skill-format.md` に従う。** 並び順（関門→参考→手順）・肯定形で書く・
同じ規則を2箇所に書かない、まで全部そこにある。

書き換えたら、**旧版の固有トークンが新版に残っているか機械照合する**（目視で「大丈夫そう」は使わない）。

```bash
python3 ~/.claude/skills/skill-creator/references/check-undug.py <SKILL.md>          # 掘り残し（測り方・道具・数）exit 0 が合格
python3 ~/.claude/skills/skill-creator/references/check-md-format.py <SKILL.md> --skill
python3 ~/.claude/skills/skill-creator/references/check-nolost.py <旧ファイル> <新ファイル>
```

**E2E の合格条件に「上の3本が全部 exit 0」を含める。** 1本でも落ちている物は成果物にしない。

## 実装の必須要件

- 構成: `SKILL.md`（**500行以内**）+ `scripts/`（決定的処理はコードに落とす）
  + `references/`（必要時のみ読む詳細）
- description は「何をするか+いつ発動するか」を具体フレーズ入りで書く
  （発動しなさすぎ対策で少し押し気味に）
- **命令形で書く。判断基準は数字で固定する**（「多い」でなく「20件以上」）
- **測定系スキルは「測定の限界」セクションを必ず入れる**（何が見えないか）
- 過去の実測で得た罠・仕様は日付付きで残す

エラー設計:

- **「0件」と「取得失敗」を必ず区別する**（ブロック/CAPTCHA/レート制限を0件と報告しない）
- リトライ+待機は script 側に組み込む。失敗時は原因を stderr に出す
- 生データ（HTML/JSON）はファイルに退避し、**Claudeは抽出済みの数行だけ読む**（トークン節約原則）
- 外部仕様変更で静かに壊れる依存には、**目視ダブルチェック手順を SKILL.md に併記**

## 前提が崩れたら書く前に設計を変える

**書いてから直すのは禁止。** プラン検証で前提が崩れたステップは、その時点でフォールバックを足すか削る。

## E2Eは端まで通す

- **本物の入力**でスキルの全手順を最初から最後まで1回通す（モックでなく実データ・実出力先）
- 全出力先（vault保存・ファイル生成等）まで動かす。**途中で止めない**
- 0件のステップがあれば Step 2 に戻って原因を切り分ける
- **直したらもう1回フルで通す**（部分再実行で済ませない）

## 報告に必ず含めるもの

- E2Eテストの実測結果（入力・出力件数・出力先パス）
- Codex指摘の要約と採否
- 既知の限界（測れないもの・壊れうる依存）

<procedure>

# 3. 実行手順

## Step 1: 意図の確定

- このスキルで何ができるようになるか / いつ発動するか / 出力形式は何か
- 会話内に既にワークフローがあるなら（「これをスキルにして」）、
  会話履歴から手順・使ったツール・ユーザーの修正指示を抽出して確認を取る
- 既存スキルと重複しないか `~/.claude/skills/` を確認。重複するなら新規でなく更新

## Step 2: プラン検証（実装前ゲート）← 必須

スキルの各ステップが**前提としている事実を、実装前に最小コストで実測確認**する。

- 外部ソースに依存するステップ → そのソースに実際に1回アクセスして、取れるか・形式は想定通りかを確認
  （例: HTMLが素のfetchで取れるか、CAPTCHAが出るか、APIが生きているか）
- ライブラリに依存するステップ → import 1発+最小呼び出しで動作確認。バージョンとAPI形状を記録
- 検証結果は SKILL.md 内に「実測済みの事実」として日付付きで残す

## Step 3: 実装

書式と必須要件は冒頭の関門に従う。

## Step 4: E2Eテスト（実測ゲート）← 必須

やり方は冒頭の関門「E2Eは端まで通す」。出た数字・件数・所要時間を記録する。

## Step 5: Codexレビュー ← 必須

`mcp__codex__codex` に以下を渡してレビューさせる。

- SKILL.md 全文 + scripts/ の全コード
- 依頼文の観点固定: 「(1)エラーハンドリングの穴（0件と失敗の混同・リトライ欠如・例外握りつぶし）
  (2)手順の論理矛盾・実行不能なステップ (3)外部依存が壊れた時の検知可能性
  (4)出力の誤解を招く表現、を指摘して。動くかどうかではなく壊れ方を見て」
- 指摘は妥当性を自分で判断して取捨選択し、採用した修正を適用 →
  **Step 4 のE2Eを再実行**して回帰確認
- Codexが使えない場合（MCP切断等）は everything-claude-code:code-reviewer agent で代替し、
  その旨を報告に明記

## Step 6: 登録+報告

置き場所と報告内容は冒頭の関門・参考に従う。

</procedure>
