# .md を書く時の形（毎回。言われなくても。聞かずにやる）

**残す .md は全部この形で書く。** 単発の書き捨て（`/tmp` の作業メモ）だけ例外。
対象: スキル、参考資料、引き継ぎ、調査結果、まとめ、手順書。**後で誰かが読む物は全部。**

**書き始める前に3つ決める。書いた後に整えると必ず作り直しになる。**
① 読者は誰か（2種類いるなら、その時点でファイルを割る）
② どう引かせるか（頭から読ませない。索引の見出しを先に書く）
③ 何を関門にするか（通らなければ着手しない条件）

1. **先頭3行で「誰が・いつ読む物か・読まなくていい条件」を書く。** 通読させない
2. **強い位置に守らせたい物を置く。** 冒頭と末尾が強く、真ん中は読まれない（U字）。
   真ん中には「引けばいいもの」だけ置く
3. **引く物には索引を付ける。** 「症状 → どこを読む」の表。頭から読ませない
4. **表にできる物は表にする。** 条件と対処の対応が一目で追える
5. **同じ規則を2箇所に書かない。** 1箇所に書いて他はそこを指す。片方だけ古くなる
6. **500行を超えたら割る。** 読者が2種類混ざっていたら、読者で割る
7. 見出しは肯定形（「Xしない」より「Yする」）。理由を1行添える

**スキルと参考資料は並び順まで固定**（`skill-format.md`）:
`関門（通らなければ着手しない）` → `参考（引く。通読しない）` → `手順（末尾）`。

**何かを作る前・書いた答えを1つ出すたびに、正本を引く（中身はここに写さない。写すとズレる）:**
`~/Documents/Obsidian Vault/ec/構造/_考え方-コンポーネント分解.md`
（割る → 部品ごとに定義 → 例を貯める、と「1段掘る」の3問。作業の型（作る／切り分ける／決める）で入口が違う）

**書き終わったら必ず機械にかける。目で「大丈夫そう」は使わない。**
```bash
python3 ~/.claude/skills/skill-creator/references/check-undug.py <file.md>      # 掘り残し。.md を書くと hook で自動でも走る（PostToolUse）
python3 ~/.claude/skills/skill-creator/references/check-md-format.py <file.md> [--skill]
# 書き換えた時は、旧版と両方向で照合する（落ちていないか／勝手に足していないか）
python3 ~/.claude/skills/skill-creator/references/check-nolost.py <旧> <新>
python3 ~/.claude/skills/skill-creator/references/check-nolost.py <新> <旧>
```

**エージェントに .md を書かせる時は、この節をプロンプトに写して渡す。**
自分の文脈は相手に伝わらないので、渡さないと必ず素の形で返ってくる。
戻ってきた物にも `check-undug.py` と `check-md-format.py` の両方をかけてから採用する。
