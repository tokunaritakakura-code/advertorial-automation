# プロンプト・スキル・文書の書き方（毎回。言われなくても）

**スキルを作る／直す時、エージェントに仕事を投げる時、直した記録を書く時は、先にこれを読む。**

```
~/.claude/skills/skill-creator/references/prompt-quality.md   ← 中身の書き方
~/.claude/skills/skill-creator/references/skill-format.md     ← 並び順
```

適当に書くと読む側が必ず間違える。特に守るもの:

1. **エージェントに投げる時**: 役割を固定 → 結論を1行目に強制 → 出力の見出しを先に列挙 →
   禁止を明示（褒めるな・一般論を書くな・推測で書くな）→ 検証手段を指定 → 引用を強制 →
   反証を3つ以上要求 → **自分の結論は渡さない** → 観点を分けて並列で回す
2. **直した記録**: 「直した」だけ書かない。**何が壊れていたかを数字と固有名で書く。**
   直していないものを同じファイルに重い順で残す。落ちた実験を消さない
3. **主張**: 母数を横に書く（n=1 なら n=1）。出どころ記号を値に付ける。
   取得失敗を0件と書かない。借り物の数字を自作の物に付けない
4. **作った物は文脈ゼロの独立エージェントに監査させる。** 自分の穴は自分では見えない
