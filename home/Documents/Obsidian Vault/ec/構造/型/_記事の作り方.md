# アドバトリアルを、参考1本から作る流れ

読む人: 参考の記事URLを渡された係。
読む時: 「この記事の型でうちの記事を作って」と言われた時。
読まなくていい条件: すでに型が決まっていて、本文を直すだけの時（その記事の移植表を見る）。

## 言葉の定義

| 言葉 | この1枚での意味 |
|---|---|
| 参考 | 他社（または自社の別ブランド）の、実際に配信されているアドバトリアル1本 |
| 型 | 参考から取り出した、並び・規則・当てている感情のセット。`A<番号>` が付く |
| 移植表 | 左に参考の段、右にうちの言葉を1段ずつ置いた表。記事の設計図 |
| 殻 | 参考のCSSだけを残した空のHTML。中身を入れれば記事になる |
| 規則 | 型ごとに決まっている数の縛り。蛍光の本数・太字ゼロの節・CTAの位置・画像の置き方の6行 |

## 入口の分岐（2026-10-04-r1 本人指定）

同じ勝ち広告の実際の遷移先を引き継ぐ。使える記事がブランド内にあり、問い・構造・商品・客像・約束・価格・証拠・CTAと版が合えば再利用する。一部だけ違えばその段を修正。無ければ作る。型だけ合う時は型を再利用して本文を書く。PDP直行なら記事を作らない。再利用元の版と不足を残し、下の新規手順を毎回全てやり直さない。

### 今回の品質確認（2026-10-04-r1）

同じ参考と既存の型・客の資料・割り付けを使い、既存の段と検査の中で次の3つを確認する。確認前にこの正本と選んだ型の `_分解.md` の版／内容hashを記録し、編集長も同じ版と元参考で見直す。モデルの一般的な自己評価だけで合格にしない。

| 見る物 | 確かめること | 本人が直せる出力 |
|---|---|---|
| コピー | 見出しと各段が、参考の意図した心理的な働き・読者の進み方を保つ。広告が渡した問いを冒頭で受け、客の資料と自社の事実で日本語に移す。直訳の言い回しだけを写さない | 左に参考、右に日本語、段の働きと必要な変更理由を置いた移植表 |
| 見た目 | 選んだ型の見出し・段・強調・画像・CTAの順と数を照合する。PCとスマホで読め、画像とリンク先が商品・記事の役割に合う | 編集できるローカルHTMLとプレビュー、該当段の確認結果 |
| 分かりやすさ | 日本語で初めて読んだ人がすぐ分かる短い具体的な文。誰が・何を・どこがを指せる。気の利いた難語・抽象語・英語の直訳を避ける。「小学5年生」は一度で分かる説明の例えで、英語の学年指標や子ども向け記事を意味しない | 移植表とHTMLの該当文をそのまま直せる形 |

参考の広告が動いているから記事も働いているはず、という考えは本人の仮説。広告の評価・継続だけで、その記事の転換率・売上・利益を実証済みとは書かない。参考の出所・利用できる素材・実際の商品事実は別に確かめ、他社の引用・人数・保証・価格を自社の実績に変えない。既存の1参考・1角度・10問・型の規則6行・計測・出口検査は残す。

## 一行で

**使える記事を確認 → 再利用／必要段を修正／新規を選ぶ → 新規で必要な時だけ参考を数えて型を作る → 10問・移植表・HTMLの不足を埋める → 規則6行と3つの品質を今回の版で確かめる。**

## 関門（通らなければ書き始めない）

| # | 関門 | 理由 |
|---|---|---|
| 1 | **型にする参考は1本だけ。混ぜない** | 別々の客に最適化された形を同時に着ることになる（[[native-ads]] 0-6） |
| 2 | **10個の問いの4番（試した物全部に共通する1つ）が出るまで書かない** | ここが型の芯。出ないままだと、競合を1つずつ落とすだけの平たい記事になる |
| 3 | **角度は1本。**1本の記事に時刻を2つ、症状を2つ入れない | 1人ではなく複数人に話しかけることになる |
| 4 | 本番へ出すのは本人の承認後。ローカルで開いて見せるまでが係の仕事 | 記憶 `no-auto-deploy-without-approval` |

## 手順

```bash
cd ~/Claude\ Code/adv-kata

# 1. 参考を機械で数える（節・蛍光・太字・CTAの位置・画像の置き方・CSSの数値）
python3 measure.py "<参考のURL>" /tmp/参考-自動.md

# 2. 同じ型が既にあるか見る
grep -n "" "$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian Vault/ec/構造/型/_一覧.md"

# 3. 作業場を作る（Obsidianの移植表と、CSSだけ入った殻）
./新規.sh A01 アルコット 夕方
```

4. **型が無ければ作る。** `構造/型/A<次の番号> <呼び名>/_分解.md` に、`/tmp/参考-自動.md` の数字と、参考の本文から引いた「何に当てている記事か（痛み・ターゲット・今の解決策・売る解決策・押している感情5つ・エンジン）」を書く
5. **10個の問いを埋める。** 客の正本は同じブランド／商品／版の `ec/<商品>/02 客/01 ペルソナ/`。値段・保証・数字はその商品の確認済み本番PDP／記事と出典から取る。他ブランドの数値は使わない。新商品で未確認なら未確認と残し、仮の価格／保証を作らない。4番が出なければ止めて本人に相談する。

   > 旧アルコット専用例（履歴、他商品への現行指示ではない）：`curl -sL https://arukoto.shop/pages/ar-insole`。
5-1. **広告を塗る（右の列を書く前の関門）。** `構造/型/_買うまでの15の事.md` の「広告を塗る」の通り、受ける広告を15の事で ◎○× に塗り、根拠の1行と「広告が言わなかった問い」を移植表の頭に書く。題はその問いに当てる。塗りが無いまま右の列を書かない（2026-10-12 本人）
6. **移植表の右の列を1段ずつ書く。** 段ごとに「どの事」（15の事の名前）と「心の声」を付け、× の事は全部書き、○ は中身を書き、◎ は同じ文を使わず人の話や別の部品で言い直す。見た目は `_見た目の手本.md` の部品8つの中で組む。 段の意図した心理効果・疑問を受ける順番を保ち、同じ商品の事実と客の資料で一読して分かる日本語にする。固有名詞の置換だけでは分かりにくい表現も書き直す。変えた表現と段の働きを移植表に記録する。

   > 旧限定置換指示（廃止履歴）：「差し替えるのは固有名詞・場面・時刻・うちの事実だけ」。
7. 殻に本文を流して `index.html` にする
8. **選んだ型の `_分解.md` の規則6行を数えて検査する。** 実際に選んだ参考／型の強調・CTA・画像順の規則を使い、別の型の数を一律に課さない。

   > Karuya型の数値例（その型を選んだ時だけ）：蛍光7〜9・1節1本／落差と手順とFAQは太字ゼロ／CTAは値段・締め・FAQ直後の3つ／浮遊CTAは解決の見出しより前に出ない／画像は見出しの前に無い。全型共通の数値ではない。
9. `open index.html` で本人に見せる。本番へ上げるのは承認が出てから
10. 型の `_分解.md` の「この型で作った記事」に1行足す。[[_一覧]] の使っているブランドの欄も直す
