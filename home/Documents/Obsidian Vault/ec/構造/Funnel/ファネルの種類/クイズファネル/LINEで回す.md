# クイズファネルを LINE で回す（Lovy を移す手順書）

読む人: クイズを作る・直す記事ライターとファネル責任者、構造に口を出す本人。
読む時: クイズの問い・幕間・結果・特典を LINE の上で作る時、直す時、抜けを測る時。
読まなくていい条件: Web だけのクイズを見る時（`_foundation.md` と `いいファネルの例/`）。文言を1か所直すだけの時は「手順」の4〜7だけ回す。

正本はここ1枚。ここちドライの今の状態（公開先・鍵・見張り）は Vault `ec/ここちドライ/女性用/04 設計/07 ファネル/03 クイズ.md`。

## 関門（通らなければ作らない・出さない）

1. **Lovy から1つずつ移す。** 問いの数・順番・分岐・幕間・レポート・結果・特典を、下の「移植表」の左列（Lovy）と1行ずつ対にして右列を書く。足す・削る時は理由を1行書く。手本は `いいファネルの例/05 Lovy（UroControl）（尿もれ（サプリ））.md`
2. **設計は1ファイルだけに書く。** 問い・選択肢・分岐・計算・結果の文言は `quiz-data.js` 1本。Web 版と LINE 版はこれを読んで画面を作るので、LINE 用に別の文言を書かない
3. **`node 検査.mjs` が 0件になるまで本人に見せない。** LINE の上限と Lovy の並び（1画面1問・進捗・値段は結果の後）を機械で数える
4. **本番は本人の承認の後だけ。** `deploy.sh`・LINE の設定（Webhook・リッチメニュー・あいさつ）・一斉配信は、本人が「上げて」と言うまで触らない。作る役の仕事は手元で動かして見せるまで
5. **うちの事実（値段・割引・保証・サイズ）は本番の店から取る**（`curl -sL https://kokochidry.shop/products/<商品>.js`）。仮の数字を入れない
6. **計測の印を外さない。** 注文ボタンは `/go` を通す（押した数を数える）。カートの URL に `attributes[source]=quiz-line` を付ける（買った数を店の注文で数える）
7. **月の通数を先に確かめる**（`curl -H "Authorization: Bearer <トークン>" https://api.line.me/v2/bot/message/quota/consumption`）。 待ちの後の画面は返信でなくプッシュで送るので、通数を食う。上限を超えると待ちの後が届かず、客が途中で止まる（「参考」の通数の節）

### LINE の機能（使う物・使わない物）

| やりたい事 | 使う機能 | 上限・注意 |
|---|---|---|
| 1画面1問・ボタンで答える | Flex Message のカード（bubble）にボタンを縦に並べる | ボタンの字40字・postback の中身300字。カードは30KBまで |
| 進捗を出す | カードの頭に【n/13問目】と「あと◯問で最大◯円OFF」 | Lovy の進捗バーの代わり |
| 複数選択 | 押すたびに返事をせず Durable Object `Sel` に貯め、「選び終わって次へ」でまとめて読む | 30分で消える。消えていたらもう一度選ばせる |
| 日付 | datetimepicker（mode: date） | |
| 待ち | `chat/loading/start`（入力中…の動き）＋小さい待ちカード | 1対1のトークだけで動く。待ちの後はプッシュになる |
| 診断を始める入口 | リッチメニューの「1分診断をはじめる」・友だち追加・何か送る | どれでも1問目から |
| 結果と特典 | Flex のカード・カルーセル（12枚まで）・URI ボタン | URL は1000字まで・https だけ |
| 割引 | 店の割引コードをカートの URL に付ける（`discount=`） | LINE のクーポン機能は使わない（店で効かない） |

使わない物と理由:

| 物 | 使わない理由 |
|---|---|
| クイックリプライ | ボタンの字が20字まで・次の発言で消える。Flex のボタンの方が答えが長く書け、押し直しにも残る |
| Lステップ・エルメの2つ（外部ツール） | 契約が無い。入れると Webhook を取られ、今の自前の返事と同じチャンネルで並べられない。月額もかかる。分岐・計算・計測は今の仕組みで足りている |
| LIFF（LINE の中で Web 版を開く） | 画面は Web 版と同じにできるが、トークの中で答える形（Lovy の1画面1問をトークで出す）を本人が選んだ。Web 版を出したくなったら `index.html` をそのまま LIFF に登録する |

### 分岐の書き方（`quiz-data.js` の中）

| したい分岐 | 書く所 | 例 |
|---|---|---|
| 答えで画面を飛ばす | 画面に `skipIf: { <問いのid>: "<答え>" }` | `date` は `event` が「特にない」なら飛ばす |
| 答えで幕間の中身を変える | `info` に `reasons`（答え → 理由と写真）と `hMine`（当てはまった時の見出し） | `why` は `tried` で選んだ物だけ理由を出す（Lovy 6 の幕間） |
| 答えで金額・度合い・サイズを変える | `calc(A)` が返す値（`paperYear`・`levelName`・`size` 等）を文言の `{...}` に差す | `cost` の3年の紙代、`report` の度合い |
| 答えで結果の言葉を変える | `reportMsg(A, c)`・`outcomeCta(A)`・`answers`（買う前の不安と答え） | `worry` で選んだ不安を結果で先に開く |

答えは `x` に詰めてボタンの中で持ち回る（1つ選ぶ=番号、複数=ビット、日付=YYYYMMDD、飛ばし=0）。サーバーに答えは残らない。

### 計測（どの問いで抜けたか）

| 何を | どこで数える | 見方 |
|---|---|---|
| 画面ごとに着いた人 | Durable Object `Tally`（同じ人は画面ごとに1回・着いた日に足す） | `node 抜け.mjs --from <日付>` |
| 特典を押した人 | 同じ（`claim`） | 同上 |
| 注文ボタンを押した人 | `/go` を通った数（`cart:<セット>`） | 同上 |
| 買った人 | 店の注文の属性 `source=quiz-line` | MCP `shopify` の GraphQL で注文の `customAttributes` を数える。割引コード `KOKOCHI2000` はメール登録と同じなので、コードでは数えない |
| 友だち追加・ブロック | LINE の `insight/followers` | 読むだけの API |

`抜け.mjs` は画面ごとに「着いた人・1問目から何%・前の画面から何%抜けたか」を出す。抜けがいちばん大きい画面を1つだけ直し、次の週に同じ表で比べる。

## 手順（毎回この順）

1. Lovy の分解（関門1のファイル）を開き、上の移植表の左列と今の `quiz-data.js` の画面を並べる。変える行だけ決める
2. 変える行の右列を書く。差し替えるのは言葉・場面・うちの事実だけで、画面の仕事（自分ごと・反論・希望・期限）は動かさない
3. `quiz-data.js` を直す。分岐は「分岐の書き方」の表の書く所に入れる。うちの事実は `curl -sL https://kokochidry.shop/products/<商品>` で本番から取る
4. `cd "03 LINE版" && node 検査.mjs` を回す。「通った: 0件」になるまで3に戻る
5. 手元で動かす: `05 Cloudflare` に `.dev.vars`（`LINE_CHANNEL_SECRET=testsecret`・`LINE_CHANNEL_ACCESS_TOKEN=invalid`・`FUNNEL_KEY=testkey`）を置いて `npx wrangler dev --local --port 8787`。署名を付けた偽の出来事を送って最後まで通し、`FUNNEL_KEY=testkey node 抜け.mjs --url http://localhost:8787` で全画面に数が入るのを見る。終わったら止めて `.dev.vars` と `.wrangler/state` を消す
6. `03 LINE版/preview.html` と Web 版を `open` し、通数（上の表）と一緒に本人に見せる
7. 本人の承認を待つ。承認の言葉が出るまで8に進まない
8. 承認の後: 初回だけ `grep WATCH_RUN_KEY ~/.config/kokochi-line/.env | cut -d= -f2 | npx wrangler secret put FUNNEL_KEY`（`05 Cloudflare` で）。続けて `./deploy.sh`。上げた後に LINE から「診断」と送って1問目が出るのと、`node 抜け.mjs` が表を返すのを確かめる。ここちドライの `03 クイズ.md` の表を1行直す
9. 1週間ごとに `node 抜け.mjs --from <先週の月曜>` を回し、抜けがいちばん大きい画面を1つだけ1に戻して直す。買った数は店の注文の `source=quiz-line` で数える（MCP `shopify`）
10. 別のブランドで回す時: `01 クイズ` をそのブランドのデスクトップの置き場に写し、`quiz-data.js`（店・商品・割引コード・バリアント）・`wrangler.jsonc` の `name`・鍵の `.env` を差し替えて、1から回す
