## 毎回の入口（2026-10-04-preflight-r3）

新規案件・再開・引き継ぎでは、役が決まっていても最初に [[_実行契約#毎回のpreflightと、依頼全体を失わない引き継ぎ（2026-10-04-preflight-r3）]] を読む。既存agent team／TREE／段の品質シートへ割り当て、元発注と最新修正・実承認の出所、依頼全体snapshot、current focus、アクセス経路・費用／操作制限、証拠・残作業・nextを引き継ぐ。今の段だけの短い指示で全体scopeを削らない。本人の明示取消は反映し、実platform拒否は迂回しない。本人に手動のtask chat管理をさせない。実コードの必須読込と新scope配線は別に未接続と記録する。

## 関門（組織の決まり。通らない役は作らない）

1. **1つの成果物に、結果の責任者（A）は1人。** 2人に決まる物は役の分け方が間違っている（RACI）
2. **作る役と確かめる役を分ける。** 確かめるのは編集長（文脈を持たない別のエージェント）か機械の検査。作った役が自分で合格を出さない（maker-checker）
3. **上の役は作業しない。** 本部長・部長は振る・発注書を書く・審査を通してから返す、の3つだけ（0xMorlex 原文 §3）
4. **役と役は発注書と引き継ぎの1行でつなぐ。** 口頭（会話の流れ）で渡さない。形は下の「発注書」と `HANDOFF:` の1行
5. **本人に届くのは決める物だけ。** 承認（配信オン・予算・本番公開・発注）と、構造の見直しの2種類。途中経過は届けない
6. **役ごとに数える物（KPI）を1つ以上持つ。** 数えられない役は、出来が良いか悪いか誰も言えない

### 発注書（役から役へ渡す形）

ブランドマネージャーがクリエイティブディレクターに出す時の形。他の部への発注も同じ欄を使う。

| 欄 | 中身 |
|---|---|
| ブランド | アルコット／ここちドライ／… |
| 狙う数字 | どの数字をどこまで動かすか（例: A02 の CPA を ¥4,000 以下に） |
| A と H | 台帳の番号。新しい A なら戦略担当への発注が先 |
| 参考 | 自社とGetHookdの2軸から選んだ物（無ければストラテジストが選ぶ） | <!-- 掘った: 参考の出どころの名前。`mcp__gethookd__search_ads` で引く -->
| 本数と種類 | VSL・静止画・ネイティブの本数 |
| 着地 | 飛ばす記事・クイズ・商品ページ |
| 締切 | 日時 |
| 使ってよい費用 | 生成のクレジットの上限（超えるなら本人の承認） |

役の終わりの形の最後に、次の1行を書く。本部長か部長がこれを読んで次の役に振る（役は別の役を直接呼べない）。

```
HANDOFF: <渡す先の役> / <渡す物のパス> / <相手にやってほしい事1文>
```

### 自動で進める案件（2026-10-06 本人「ニッチで新しい商品に行くと言ったら、起きた頃には出せる広告・記事・商品ページがある」）

本人の発注に `autopilot: {goal}` が付いた案件は、本部長の「次へ渡す」を機械（`~/Claude Code/team-room/autopilot.mjs`）がやる。部長が終わるたびに返事の最後の `HANDOFF:` 行を読み、その発注の中で編集長が PASS を出していれば、渡す先の部長に発注を書く（書き手は「自動の振り分け」）。

| 場合 | どうなる |
|---|---|
| 編集長 PASS＋HANDOFF が次の部長宛て | 次の部へ自動で発注。元の発注とゴールを毎回付ける |
| HANDOFF が「本人」宛て・編集長の PASS が無い・部長が最後まで終わらない・同じ発注が2回続く・40回渡した | 止めて、Telegram で1通（✅ 揃った／⏸ 止まった＋理由） |

- 自動の案件では、部長は途中で本人に判断を聞かない。手順書と客の声の数で決め、理由を残す（工程3の「今週の A」はこれで代える。**ただし工程4の入口の「どんな広告を・どのフォーマットで・何本」と、ローンチ／ローンチ後の参考の分かれ道、リップの本数は、自動の案件でも毎回本人に聞いて止まる**（2026-10-07 本人。`役/クリエイティブディレクター.md` 関門0-1・0-2））
- 「本人」宛てにしてよいのは、本番公開・配信・予算・お金のかかる発注しか残っていない時か、ゴールの物が全部揃った時だけ
- 止める: `curl -X POST localhost:3200/api/autopilot -d '{"context":{…},"stop":true}'`。状態は `team-room/data/autopilot.json`

## 手順（役を1つ作る・直す時）

1. `agent-team` スキルを起動し、原文を全文読む
2. 上の「役の一覧」の行を1つ選び、その役の手順書を `ec/構造/ハーネス/役/<役の名前>.md` に書く。中身は 仕事1文・ルール・終わりの形・読む物・渡す物（`HANDOFF:` の1行）・数える物・触っていい物／準備まで／禁止
3. 作った役の成果物を確かめる検査を1つ以上作る（作る役と確かめる役を分ける）
4. 実際の入力で1回回し、「入った件数・本人に届いた件数・本人が直した件数」を実行ログに書く
5. この表の「状態」と [[_参考再現フロー_工程と関門_2026-10-03.canvas]] の色を直す
